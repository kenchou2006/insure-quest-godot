### P2 問題：新人顧問卡在哪
**標題：訓練了商品知識，卻沒訓練「怎麼問、怎麼說」**

| 痛點 | 後果 |
|---|---|
| 只學商品話術，不會挖需求 | 客戶感覺被推銷，成交品質低 |
| 話術不合規（保證報酬、恐嚇式銷售、與存款比較、施壓） | 錯誤銷售、客訴、裁罰風險 |
| 看不到規劃的長期後果 | 無法理解「適合」比「賣出」重要 |
| 教室角色扮演難擴大、難量化 | 訓練成效無數據、教官負擔重 |

**講者備註**：對應主辦方「銷售與通路賦能」情境。⚠️若有可引用的公開資料（金管會裁罰案例、保險業客訴統計），在此加一則並標註出處，沒有就不要放數字。

### P3 我們的解法（一頁看懂）
**標題：把一次客戶訪談，做成大富翁的一格**

流程圖（一行）：
`擲骰 → 走到客戶格 → 看場景找線索 → 3 輪開放式對話 → 配置 10 枚資源幣 → 90 天壓力測試 → 十年財務時間軸 → 十年後的信`

三個層次：
- **遊戲層**：大富翁棋盤、事件、聲望、旁觀預測
- **訓練層**：需求訪談、合規雷達、規劃配置
- **數據層**：決策軌跡、弱點標籤、教官看板

### P4 題目對應：為什麼是「保險大富翁」
**標題：大富翁的機制，天然適合訓練「人生風險」**

| 大富翁元素 | 本作的轉譯 |
|---|---|
| 棋盤與骰子 | 人生路徑上的客戶、機會與事件 |
| 地產 | 客戶的家庭與資產（18 位虛構客戶） |
| 機會／命運 | 人生插曲（失業、傷病、市場下跌）與終局「全球金融海嘯」 |

| 玩家資產 | **聲望**（Prestige），不是錢；說錯話會扣聲望 |

**講者備註**：強調我們沒有拿保險當獎勵商品，而是拿「客戶的人生」當棋盤。

### P5 遊戲核心循環（Demo 截圖頁）
**標題：一局遊戲長這樣**
- 2–4 人線上，或單人對機器人顧問
- 回合：擲骰 → 事件／客戶 → 訪談 → 結算
- 終局：最後一輪觸發「全球金融海嘯」，所有人的客戶同時受測
- 截圖：棋盤＋右側資訊面板（`docs/design/round4-shots/`）

### P6 需求訪談：問對才有線索
**標題：線索不會自己跳出來，要用好問題換**
- 每位客戶有隱藏需求、場景插圖中藏 3 個線索＋1 個干擾物
- 3 輪開放式對話：建議問題按鈕＋自由輸入
- 好問題提升信任與洞察，才揭露線索
- 視覺：session_panel 對話畫面（視覺小說式對話泡泡）

**講者備註**：這是「需求導向銷售」的核心：不是選答案，是「問」。

---

### P7 合規雷達：每句話都被看著
**標題：說錯話，當下就亮紅燈**

| 違規類型 | 例句 | 系統反應 |
|---|---|---|
| 保證報酬 | 「保證穩賺 5%」 | 紅燈＋改寫建議 |
| 恐嚇式銷售 | 「不買出事你就完了」 | 紅燈 |
| 與存款比較誤導 | 「比定存好太多」 | 黃／紅燈 |
| 施壓成交 | 「今天不簽就沒有了」 | 紅燈 |

- 規則即時判定＋AI 補強判斷，後者到達即覆蓋
- **後果**：紅燈使評等上限為 C、案件被標記稽核（聲望 −10）、十年後的信變成客訴副本
- 引用規範僅列名稱：《金融消費者保護法》、《保險業招攬廣告自律規範》、金管會公平待客原則（⚠️放條號前須核對）

---

### P8 規劃配置：10 枚資源幣的取捨
**標題：沒有標準答案，只有「適不適合這個家庭」**
- 10 枚資源幣分配到保障／儲蓄／成長
- 保障型保障卡為功能性概念，**不對應任何真實商品**
- 客戶收入、支出、儲蓄各不相同，配置須回應訪談所得的需求
- 視覺：配置畫面截圖

---

### P9 壓力測試與十年財務時間軸
**標題：保險不會讓客戶更有錢，它讓最糟的那一年不致崩潰**
- 90 天壓力測試 → 強／中／弱三種結局
- 十年時間軸圖（`timeline_chart.gd`）：**有規劃 vs 沒規劃**的淨資產曲線
- 第 2、5、8 年各一次人生事件；現金 → 成長資產（市場下跌強制賣出損失 15%）→ 負債
- 模型為教學假設（現金年 1%、成長年 5%、保障幣每枚 = 年收入 1% 保費）

**講者備註**：這頁是「後果可見」的最強證據，建議放時間軸動態截圖。誠實講「模型假設」，反而加分。

### P10 十年後的信
**標題：結果由規則決定，信由 AI 寫**
- 規則引擎決定結局與缺口金額；AI 只負責文字
- 感謝信 vs 後悔信，並以驗證避免「感謝信裡出現後悔用語」
- 違規者收到的是**投訴副本**
- 訪客以範本信取代，不耗 AI

**講者備註**：全簡報情緒高點。可念一小段信（先準備好實際產出）。

### P11 AI 應用總覽
**標題：AI 用在「對話、判斷、文字」，不用在「勝負」**

| AI 角色 | 功能 |
|---|---|
| AI 客戶 | 有人設、隱藏需求、動態人生插曲 |
| 合規稽核 | 語句判斷＋改寫建議 |
| 教練 | 一場一次提示（扣 2 聲望），指方向不給答案 |
| 內容生成 | 反對意見評分、總結點評、新客戶、十年後的信 |

- 每輪對話把「客戶回應＋線索＋信任變化＋合規＋教練」併成 **單次結構化呼叫**，每場訪談 ≤ 3 次
- zod 驗證，失敗退款並退回規則引擎

---

### P12 AI 護欄與可靠性
**標題：AI 可以失敗，遊戲不會壞**

| 風險 | 設計 |
|---|---|
| AI 亂給分數／金額 | 結局、分數、金額**只由確定性規則引擎決定** |
| Prompt injection | 玩家輸入包成不可信資料，且注入嘗試本身被判為合規問題 |
| 模型不可用 | NVIDIA NIM → NIM 備援模型 → Workers AI → 規則引擎 |
| 個資外流 | 提示詞只含虛構客戶與玩家發言，不含姓名／Email／ID |
| 輸出品質 | 信件結果與措辭做一致性驗證 |

### P16 技術架構與可行性
**標題：一個 Worker、一次部署、同網域**

```
Browser (Godot Web / PWA)
   │ 同網域
   ▼
Cloudflare Worker
   ├─ Workers Static Assets：Godot 匯出檔
   ├─ Room Durable Object：每房一個，伺服器權威遊戲邏輯
   ├─ Records Durable Object：個人分片 + 全域匯總
   └─ NVIDIA NIM → Workers AI → 規則引擎
```

- 訪客單人遊玩完全在瀏覽器執行（`web/local-room.js`），不耗伺服器
- GitHub Actions：check → build → deploy 一條龍
- 測試：`npm run check`（型別＋單元測試＋平衡模擬）

### P17 隱私、安全與成本
**標題：資料少、隔離好、成本低**
- Google OAuth 全在 Worker 內處理，HttpOnly Cookie，權杖不到前端
- 每位學員獨立 Durable Object 分片（隔離的 SQLite，閒置休眠）
- 全部客戶皆虛構；保障卡為功能概念，非保險建議
- 成本：1 Worker＋2 個 DO 類別＋靜態資產；AI 以日額度與備援控制
- ⚠️若要報實際月費，請以實測用量填寫，勿估算
